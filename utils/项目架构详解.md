## 1. 项目概述

### 1.1 项目背景与功能

本项目是一个运行在工控机（后端）的多线程视频识别与数据联动系统，并配套两台触控显示电脑（前端）进行可视化与交互控制。该系统能够：

- **实时视频流处理**：同时处理多路海康威视摄像头的热成像和可见光视频流
- **温度数据分析**：通过海康SDK获取精确的温度矩阵数据，进行高温目标检测
- **多路视频推流**：使用FFmpeg API将处理后的视频流推送到本地RTSP服务器（四路：一位端/二位端的可见光与热成像）
- **智能定位上报**：通过RS422串口读取GYK协议数据，解析并重编码为48字节CAN格式负载，附带四路检测位与CRC16，经TCP广播给前端客户端
- **实时可视化**：将温度数据与视频帧融合，实现目标识别和可视化处理

### 1.3 技术栈介绍

#### 核心框架与库
- **C++17**：主要编程语言，现代C++特性支持
- **OpenCV 4.x**：计算机视觉和图像处理核心库
- **FFmpeg**：音视频编解码和流媒体传输
- **CUDA**：GPU加速图像格式转换（BGR→YUV420P）

#### 网络通信技术
- **RTSP协议**：实时流传输协议，用于视频流的拉取和推送
- **海康威视SDK (HCNetSDK)**：设备控制和数据获取
- **Winsock2**：Windows套接字编程，UDP通信实现

#### 硬件通信协议
- **CAN总线**：Controller Area Network，工业现场总线通信
- **扩展帧格式**：29位帧ID，支持复杂的多设备通信

#### 并发编程
- **std::thread**：C++11标准线程库
- **std::mutex**：互斥锁，保证线程安全
- **std::atomic**：原子操作，无锁编程
- **智能指针**：`std::unique_ptr`自动内存管理

#### 数据处理
- **JSON配置**：nlohmann/json库，配置文件解析
- **图像处理**：温度矩阵分析、目标检测、轮廓提取
- **CRC校验**：数据完整性验证

### 2.1 多线程架构设计

本系统采用**生产者-消费者模式**的多线程架构，通过`SharedData`作为中央数据交换中心：

```cpp
// ThreadManager.h - 线程管理器设计
class ThreadManager {
private:
    std::unique_ptr<TaskVideoCapture> taskVideo_;     // 视频捕获任务
    std::unique_ptr<TaskThermalCapture> taskThermal_; // 热成像捕获任务
    std::unique_ptr<TaskDisplay> taskDisplay_;        // 显示任务
    std::unique_ptr<TaskRTSPStream> taskRTSPStream_;  // RTSP推流任务
    std::unique_ptr<TaskLocating> taskLocating_;      // 定位任务
};
```

**智能指针管理的优势**：
- `std::unique_ptr`确保每个任务对象有唯一所有权
- 自动内存管理，避免内存泄漏
- 析构函数自动调用，确保资源安全释放

### 2.4 线程同步和互斥锁机制

```cpp
// 典型的线程安全数据访问模式
void someTask() {
    cv::Mat localFrame;
    {
        std::lock_guard<std::mutex> lock(data_.thermalframe_Mutex_1);
        if (!data_.thermal_video_frame_1.empty()) {
            data_.thermal_video_frame_1.copyTo(localFrame);  // 数据拷贝到局部变量
        }
    } // 自动解锁
    
    // 在锁外进行耗时操作
    if (!localFrame.empty()) {
        processFrame(localFrame);
    }
}
```

**RAII锁管理优势**：
- `std::lock_guard`确保异常安全
- 作用域结束自动解锁
- 避免死锁和忘记解锁的问题

### 3.2 海康威视设备登录过程

```cpp
// main.cpp - 海康设备登录实现
bool initializeHikvisionSDKAndLogin(const char* ip, int port, 
                                   const char* username, const char* password, 
                                   LONG& lUserID) {
    const int maxRetries = 15;     // 最大重试次数
    const int retryDelayMs = 2000; // 重试间隔（毫秒）

    for (int attempt = 1; attempt <= maxRetries; ++attempt) {
        // 设置登录参数
        NET_DVR_USER_LOGIN_INFO loginInfo = { 0 };
        strcpy_s(loginInfo.sDeviceAddress, ip);    // 设备IP地址
        loginInfo.wPort = port;                    // 设备端口
        strcpy_s(loginInfo.sUserName, username);   // 用户名
        strcpy_s(loginInfo.sPassword, password);   // 密码

        // 登录设备
        NET_DVR_DEVICEINFO_V40 deviceInfo = { 0 };
        lUserID = NET_DVR_Login_V40(&loginInfo, &deviceInfo);
        
        if (lUserID >= 0) {
            std::cout << "设备登录成功！" << std::endl;
            return true; // 登录成功
        } else {
            std::cerr << "设备登录失败，错误码: " << NET_DVR_GetLastError() << std::endl;
            NET_DVR_Cleanup(); // 清理SDK资源
            std::this_thread::sleep_for(std::chrono::milliseconds(retryDelayMs));
        }
    }
    return false; // 重试失败
}
```

**关键技术点**：
- **重试机制**：网络设备连接不稳定，需要多次尝试
- **错误码检查**：`NET_DVR_GetLastError()`获取具体失败原因
- **资源清理**：失败时及时调用`NET_DVR_Cleanup()`

```cpp
// main.cpp - 视频流连接初始化
bool initializeVideoStream(std::unique_ptr<cv::VideoCapture>& cap, 
                          const std::string& url, 
                          const std::string& errorMessage) {
    cap->open(url); // 打开视频流
    if (!cap->isOpened()) {
        std::cerr << errorMessage << std::endl;
        return false; // 如果打开失败，返回false
    }
    cap->set(cv::CAP_PROP_BUFFERSIZE, 3); // 设置缓冲区大小为3，减少延迟
    return true; // 初始化成功
}
```

**缓冲区设置的重要性**：

- 减少视频延迟，适合实时应用
- 避免缓冲区积累过多旧帧

### 4.1 RTSP视频流技术

#### RTSP协议基础知识

RTSP（Real-Time Streaming Protocol）是一种应用层网络协议，专门设计用于实时流媒体传输。与HTTP类似，RTSP使用客户端-服务器模型，但针对流媒体进行了优化。

**RTSP协议特点**：
- **实时性**：专为低延迟流媒体设计
- **状态控制**：支持播放、暂停、快进等操作
- **多路复用**：一个RTSP会话可以包含多个媒体流
- **传输协议无关**：可以使用UDP、TCP或RTP传输

#### 海康威视RTSP地址构成

```cpp
// RTSP地址格式：rtsp://用户名:密码@设备IP/Streaming/Channels/通道号
std::string thermal_url = "rtsp://" +
    device["username"].get<std::string>() + ":" +     // admin
    device["password"].get<std::string>() + "@" +     // password123
    device["ip"].get<std::string>() +                 // 192.168.1.15
    "/Streaming/Channels/" +
    std::to_string(device["thermal_channel"].get<int>()); // 201
    
// 最终地址: rtsp://admin:password123@192.168.1.15/Streaming/Channels/201
```

**海康威视通道编码规则**：
- **主码流**：通道号 × 100 + 01 (如：通道2主码流 = 201)
- **子码流**：通道号 × 100 + 02 (如：通道2子码流 = 202)  
- **热成像通道**：通常使用通道2(201)，分辨率较高
- **可见光通道**：通常使用通道1(101)，用于对比参考

```cpp
    // 1. 分配YUV420P帧
    AVFrame *frame = av_frame_alloc();
    frame->format = AV_PIX_FMT_YUV420P;
    frame->width = width_;
    frame->height = height_;
    av_frame_get_buffer(frame, 32);

    memcpy(frame->data[0], yuv.data(), width_ * height_);                    // Y分量
    memcpy(frame->data[1], yuv.data() + width_ * height_, width_ * height_ / 4);         // U分量  
    memcpy(frame->data[2], yuv.data() + width_ * height_ * 5 / 4, width_ * height_ / 4); // V分量

    if (avcodec_send_frame(codec_ctx_, frame) >= 0) {
```

### 4.3 CAN总线通信技术

#### CAN协议基础概念

CAN（Controller Area Network）是一种串行通信协议，最初为汽车电子系统设计，现广泛应用于工业控制领域。

**CAN协议核心特性**：
- **多主结构**：任何节点都可以主动发送数据
- **消息仲裁**：基于帧ID的优先级仲裁机制  
- **错误检测**：CRC校验、帧检查、应答检查
- **总线拓扑**：所有节点共享同一条总线
- **实时性强**：确定性的消息传输延迟

#### 29位扩展帧格式详解

本项目使用29位扩展帧格式，相比11位标准帧能承载更多信息：

```cpp
// TaskLocating.cpp 中的帧ID构造逻辑
struct CANFrameID {
    uint32_t frameNo   : 8;  // 帧序号 (0-255)
    uint32_t packNo    : 8;  // 包序号 (0-255)  
    uint32_t srcAddr   : 4;  // 源地址 (0-15)
    uint32_t destAddr  : 4;  // 目标地址 (0-15)
    uint32_t cmd       : 5;  // 命令字段 (0-31)
    uint32_t reserved  : 2;  // 保留位
};

// 实际使用中的帧ID计算 - 29位扩展帧格式
uint32_t constructFrameID(uint8_t cmd, uint8_t dest, uint8_t src, 
                         uint8_t pack, uint8_t frame) {
    return ((cmd & 0xFF) << 25) |     // 命令字:   8位 (位25-31，实际使用8位)
           ((dest & 0x1F) << 18) |    // 目的地址: 5位 (位18-22)
           ((src & 0x1F) << 11) |     // 源地址:   5位 (位11-15)  
           ((pack & 0x07) << 8) |     // 包序号:   3位 (位8-10)
           (frame & 0xFF);            // 帧序号:   8位 (位0-7)
}
```

#### 位域功能详解

**1. 命令字段（CMD）- 8位**：

```cpp
// TaskLocating.cpp - CAN数据发送实现
void TaskLocating::locationReport() {
    // 1. 构建待发送数据（示例：GPS+时间戳+温度数据）
    std::vector<uint8_t> totalData;
    
    // GPS数据 (12字节)
    appendGPSData(totalData);
    
    // 时间戳 (8字节)  
    appendTimestamp(totalData);
    
    // 热成像目标位置 (可变长度)
    appendThermalTargets(totalData);

    // 2. 计算需要的帧数 (每帧8字节数据)
    const size_t bytesPerFrame = 8;
    size_t totalFrames = (totalData.size() + bytesPerFrame - 1) / bytesPerFrame;
    
    if (totalFrames > 256) {
        std::cerr << "数据过大，超过256帧限制" << std::endl;
        return;
    }

    // 3. 分帧发送
    for (size_t frame = 0; frame < totalFrames; frame++) {
        CAN_DataFrame canFrame;
        
        // 构造帧ID
        canFrame.dwID = constructFrameID(CMD_THERMAL_REPORT,
                                        ADDR_MAIN_CONTROLLER,
                                        ADDR_THERMAL_SENSOR,
                                        current_pack_number_,
                                        static_cast<uint8_t>(frame));
        
        canFrame.bExternFlag = 1;  // 使用29位扩展帧
        canFrame.bRemoteFlag = 0;  // 数据帧
        canFrame.nDataLen = 8;     // 数据长度
        
        // 复制数据到CAN帧
        size_t dataStart = frame * bytesPerFrame;
        size_t dataEnd = std::min(dataStart + bytesPerFrame, totalData.size());
        
        memcpy(canFrame.arryData, &totalData[dataStart], dataEnd - dataStart);
        
        // 发送CAN帧
        if (CAN_ChannelSend(deviceHandle_, 0, &canFrame, 1) != CAN_RESULT_OK) {
            std::cerr << "CAN帧发送失败，帧序号: " << frame << std::endl;
        }
        
        std::this_thread::sleep_for(std::chrono::milliseconds(1)); // 防止总线拥塞
    }
    
    current_pack_number_++;  // 准备下一批数据
}
```

#### CRC16校验算法实现

```cpp
// TaskLocating.cpp - CRC16校验实现
uint16_t TaskLocating::calculateCRC16(const std::vector<uint8_t>& data) {
    uint16_t crc = 0xFFFF;  // CRC初始值
    
    for (uint8_t byte : data) {
        crc ^= byte;  // 与当前字节异或
        
        for (int i = 0; i < 8; i++) {
            if (crc & 0x0001) {
                crc = (crc >> 1) ^ 0xA001;  // CRC-16-IBM多项式
            } else {
                crc >>= 1;
            }
        }
    }
    
    return crc;
}

// 使用CRC校验的数据发送
void send_with_crc(std::vector<uint8_t>& combinedData) {
    // 计算CRC16校验码
    uint16_t crc = calculateCRC16(combinedData);
    
    // 将CRC添加到数据末尾（低字节在前，高字节在后）
    combinedData.push_back(static_cast<uint8_t>(crc & 0xFF));        // CRC低字节
    combinedData.push_back(static_cast<uint8_t>((crc >> 8) & 0xFF)); // CRC高字节
    
    // 然后进行多帧发送...
}
```

**CRC校验的重要性**：
- **数据完整性验证**：检测传输过程中的位错误
- **工业标准**：CRC-16-IBM是常用的工业校验算法
- **低开销**：16位校验码只增加2字节开销
- **错误检测能力**：能检测99.998%的数据错误

```cpp
        // 缓存帧数据
        frameBuffer[pack].insert(frameBuffer[pack].end(),
                                frame.arryData, 
                                frame.arryData + frame.nDataLen);
        
        // 检查是否接收完整（简化逻辑）
        if (isPacketComplete(pack)) {
            processCompletePacket(frameBuffer[pack]);
            frameBuffer.erase(pack);
        }
    }
}
```

```cpp
// WinsockSender构造函数实现
WinsockSender::WinsockSender(const std::string& ip, int port)
    : ip_(ip), port_(port), socket_(INVALID_SOCKET) {
    
    // 1. 初始化 Winsock 库
    WSADATA wsaData;
    if (WSAStartup(MAKEWORD(2, 2), &wsaData) != 0) {
        throw std::runtime_error("Winsock 初始化失败");
    }

    // 2. 创建UDP套接字
    socket_ = socket(AF_INET,      // IPv4地址族
                    SOCK_DGRAM,    // 数据报套接字(UDP)
                    IPPROTO_UDP);  // UDP协议
    
    if (socket_ == INVALID_SOCKET) {
        WSACleanup();
        throw std::runtime_error("创建套接字失败");
    }

    // 3. 设置目标地址
    setupServerAddress();
}
```

- 支持IPv6和高级套接字选项

#### 目标地址结构体配置详解

```cpp
void WinsockSender::setupServerAddress() {
    // 1. 清零地址结构体，确保所有字段初始化
    memset(&serverAddr_, 0, sizeof(serverAddr_));
    
    // 2. 设置地址族为IPv4
    serverAddr_.sin_family = AF_INET;
    
    // 3. 端口号转换：主机字节序 → 网络字节序
    serverAddr_.sin_port = htons(port_);
    
    // 4. IP地址转换：点分十进制字符串 → 网络字节序二进制
    inet_pton(AF_INET, ip_.c_str(), &serverAddr_.sin_addr);
}
```

**网络字节序转换的重要性**：

#### UDP数据发送实现

```cpp
void WinsockSender::sendData(const std::vector<uint8_t>& data) const {
    // 1. 地址类型转换
    sockaddr* addr = const_cast<sockaddr*>(
        reinterpret_cast<const sockaddr*>(&serverAddr_));
    
    // 2. 发送UDP数据报
    int result = sendto(
        socket_,                                           // 套接字
        reinterpret_cast<const char*>(data.data()),       // 数据指针
        data.size(),                                       // 数据大小
        0,                                                 // 标志位
        addr,                                             // 目标地址
        sizeof(serverAddr_)                               // 地址结构大小
    );
    
    // 3. 错误检查
    if (result == SOCKET_ERROR) {
        int error = WSAGetLastError();
        std::cerr << "UDP发送失败，错误码: " << error << std::endl;
        
        // 常见错误码处理
        switch (error) {
            case WSAECONNRESET:
                std::cerr << "连接被重置" << std::endl;
                break;
            case WSAETIMEDOUT:
                std::cerr << "发送超时" << std::endl;
                break;
            case WSAEHOSTUNREACH:
                std::cerr << "主机不可达" << std::endl;
                break;
            default:
                std::cerr << "未知网络错误" << std::endl;
        }
    }
}
```

```cpp
- 广播支持：可以发送广播和组播消息
```

### 5.2 热成像数据捕获（TaskThermalCapture）

#### 核心功能（与当前实现对齐）
- 通过 `TaskVideoCapture` 启动海康SDK的“实时测温长连接”，实时获取环境温度信息与规则温度（用于门限参考），存入 `SharedData::realtimeTemp_1/2`。
- `TaskThermalCapture` 基于热成像视频帧的灰度阈值与温度条区域的分位数估计，生成近似的温度矩阵（CV_32FC1，640×512），写入 `SharedData::thermalMatrix_1/2`。

#### 流程要点
- 初始化一次温度条ROI，计算灰度分布的指定分位数作为阈值（默认80%）；
- 对非屏蔽区域进行阈值分割，得到二值化“高/低温”矩阵；
- 按 1280×720 → 640×512 缩放，并输出 CV_32FC1；
- 可通过 `SharedData::thermalProcessingConfig` 动态启停与阈值门控。

#### 设计权衡
- 该方案在不拉取设备原生温度矩阵的前提下，结合“实时测温”与“图像灰度阈值”实现近似温度分布，计算开销低且满足实时性；
- 若后续设备开放每像素温度矩阵接口，可平滑替换为SDK原生矩阵以提高绝对精度。

```cpp
void TaskLocating::processThermalData(const cv::Mat& thermalMatrix, SharedData& data) {
    // 温度阈值分割
    cv::Mat thresholdMask;
    float threshold;
    {
        std::lock_guard<std::mutex> lock(data.alarmThresholdMutex);
        threshold = data.g_alarmThreshold;
    }
    
    cv::threshold(thermalMatrix, thresholdMask, threshold, 255, cv::THRESH_BINARY);
    thresholdMask.convertTo(thresholdMask, CV_8UC1);
    
    // 查找高温区域轮廓
    std::vector<std::vector<cv::Point>> contours;
    cv::findContours(thresholdMask, contours, cv::RETR_EXTERNAL, cv::CHAIN_APPROX_SIMPLE);
    
    // 检测新目标
    std::vector<cv::Point2f> currentObjects;
    for (const auto& contour : contours) {
        if (cv::contourArea(contour) > 100) {
            cv::Moments m = cv::moments(contour);
            cv::Point2f center(m.m10 / m.m00, m.m01 / m.m00);
            currentObjects.push_back(center);
        }
    }
    
    // 去重逻辑：检查是否为新目标
    {
        std::lock_guard<std::mutex> lock(trackedObjectsMutex_);
        for (const auto& obj : currentObjects) {
            bool isNewObject = true;
            for (const auto& tracked : trackedObjects_) {
                if (cv::norm(obj - tracked) < 50.0f) { // 50像素阈值
                    isNewObject = false;
                    break;
                }
            }
            
            if (isNewObject) {
                trackedObjects_.push_back(obj);
                std::cout << "检测到新高温目标，位置: (" << obj.x << ", " << obj.y << ")" << std::endl;
                locationReport(); // 上报定位信息
            }
        }
    }
}
```

### 5.6 统一定位上报（TaskLocationReporter）

#### 职责
- 作为“统一上报协调器”，定期读取四路检测标志位：
  - `camera1_visible_detected`、`camera1_thermal_detected`、`camera2_visible_detected`、`camera2_thermal_detected`
- 通过 `LocationReporter`：
  1) 从RS422读取GYK协议帧 → 解析核心字段（时间/速度/公里标/车次/机车号）；
  2) 转为48字节CAN负载；
  3) 按协议组帧：报头(0xAA) + 4字节检测位 + 48字节CAN + CRC16 + 报尾(0xFF)；
  4) 通过内置TCP服务器广播给已连接的前端客户端。

#### 关键点
- 原始串口数据读取失败时，具备数据连续性保障：优先复用上一帧有效数据，否则降级为内置模拟GYK数据；
- CRC16(0xA001)覆盖报头到CAN数据段，确保前端校验一致；
- 广播机制保障触控电脑A/B均能同时接收与解析。

### 5.7 控制服务器（ControlServer）

#### 职责
- 建立简单的文本协议控制通道，支持多客户端连接与广播：
  - 前端发送：`CMD:SET_DIR:1` 或 `CMD:SET_DIR:2`
  - 后端广播：`NOTIFY:SHOW_DIR:1\n` 或 `NOTIFY:SHOW_DIR:2\n`
- 触控电脑A/B均可发起控制请求；后端负责向所有连接的客户端广播，保持前端状态一致性。

#### 实现要点
- 基于Winsock2（TCP），SO_REUSEADDR，独立accept与client处理线程；
- 连接管理与异常清理，保证高可用；
- 与 `LocationReporter` 的数据广播互不影响（独立通道）。

### 5.8 原始可见光视频保存（基于海康SDK）

#### 职责与流程
- 在 `TaskVideoCapture` 中为可见光通道创建独立预览句柄，调用 `NET_DVR_SaveRealData_V30` 进行本地录制；
- 支持“文件切片”与“容量上限+回收”策略：
  - 配置最大单文件大小（MB），由SDK自动切片；
  - 后台存储监控线程定期统计目录体量，超限自动删除最旧片段直至回落到指定阈值；
- 保障推流/检测与录像相互解耦，避免IO阻塞影响实时性。

**智能指针优势体现**：
- **自动释放**：析构函数自动调用，无内存泄漏风险
- **异常安全**：构造失败时已构造对象自动清理
- **所有权明确**：`unique_ptr`确保唯一所有权
- **性能优秀**：零开销抽象，运行时无额外成本

```cpp
void WinsockSender::sendData(const std::vector<uint8_t>& data) const {
    try {
        int result = sendto(socket_, 
                           reinterpret_cast<const char*>(data.data()),
                           data.size(), 0, addr, sizeof(serverAddr_));
        
        if (result == SOCKET_ERROR) {
            handleNetworkError(WSAGetLastError());
        }

void WinsockSender::handleNetworkError(int errorCode) {
    switch (errorCode) {
        case WSAECONNRESET:
            std::cerr << "连接被远程主机重置" << std::endl;
            // 尝试重新建立连接
            reconnect();
            break;
            
        case WSAETIMEDOUT:
            std::cerr << "网络发送超时" << std::endl;

            break;

    }
```

```cpp
bool initializeHikvisionSDKAndLogin(/* 参数 */, LONG& lUserID) {
    const int maxRetries = 15;
    int retryDelay = 1000; // 初始延迟1秒
    
    for (int attempt = 1; attempt <= maxRetries; ++attempt) {
        try {
            // 尝试登录逻辑
            if (attemptLogin(/* 参数 */, lUserID)) {
                std::cout << "第" << attempt << "次尝试登录成功" << std::endl;
                return true;
            }
            
        } catch (const std::exception& e) {
            std::cerr << "登录异常: " << e.what() << std::endl;
        }
        
        std::cerr << "第" << attempt << "次登录失败，" << retryDelay << "ms后重试" << std::endl;
        std::this_thread::sleep_for(std::chrono::milliseconds(retryDelay));
        
        // 指数退避：每次失败后延迟时间翻倍，最大10秒
        retryDelay = std::min(retryDelay * 2, 10000);
    }
```

```
? 推流输出25fps：广播标准帧率，网络友好
? 定位上报10Hz：实时性与网络带宽的平衡
```

**数据一致性保证**：
- 所有线程通过`copyTo()`获得数据快照，避免读写冲突
- 使用细粒度锁，每种数据类型独立加锁
- 生产者优先策略，消费者获取最新可用数据
- 原子变量控制全局状态，确保线程安全退出
