# TaskThermalCapture 性能分析与优化指南

## 📊 性能监控功能概述

已为 `TaskThermalCapture` 添加了详细的性能监控和缓存优化功能，用于检测温度矩阵更新速度和识别性能瓶颈。

## 🕒 新增的时间戳监控

### 1. 微秒级精度监控
- 使用 `std::chrono::high_resolution_clock` 进行微秒级时间测量
- 每个处理步骤都有独立的时间戳记录

### 2. 详细的步骤分解

| 步骤 | 监控项目 | 预期耗时范围 |
|------|----------|-------------|
| 步骤1 | 获取视频帧 | 10-100 μs |
| 步骤2 | 获取温度范围 | 5-50 μs (缓存命中时更快) |
| 步骤3a | 提取调色板 | 100-500 μs |
| 步骤3b | 创建掩码 | 50-200 μs |
| 步骤3c | 图像预处理 | 500-2000 μs |
| 步骤3d | 像素计算 | **5000-15000 μs** (最耗时) |
| 步骤4 | 存储数据 | 10-100 μs |

## 🚀 缓存优化机制

### 温度数据缓存
```cpp
// 500ms缓存超时机制
const auto cacheTimeout = std::chrono::milliseconds(500);

// 缓存命中避免频繁锁定SharedData
bool getCachedTemperatureRange(int deviceIdx, float &minTemp, float &maxTemp)
```

**缓存优势**：
- 减少互斥锁竞争，提高并发性能
- 避免频繁读取实时温度数据
- 即使实时测温更新较慢，也能保持稳定的处理频率

## 🔍 性能瓶颈分析

### 预期的主要耗时环节

1. **像素级温度计算** (最耗时 70-80%)
   - 640×512 = 327,680 像素需要逐一处理
   - 每个像素需要灰度值→温度值的映射计算
   - **优化建议**: 考虑使用查找表(LUT)代替实时计算

2. **图像预处理** (第二耗时 15-20%)
   - BGR→灰度转换
   - 图像缩放 (1280×720 → 640×512)
   - **优化建议**: 可以考虑使用GPU加速或者降低处理精度

3. **调色板提取** (较小耗时 3-5%)
   - 每帧都需要重新提取温度条
   - **优化建议**: 可以缓存调色板数据，只在检测到变化时更新

## 🎯 理论性能目标

### 帧率分析
- **视频流帧率**: 通常25-30fps
- **理论处理能力**: 如果单帧处理时间 < 33ms，可以跟上30fps
- **实际目标**: 保持在20-25ms内完成单帧处理

### 实时性要求
```
期望性能指标：
- 平均处理时间: < 20ms/帧
- 处理帧率: > 50fps  
- 缓存命中率: > 80%
- 温度数据延迟: < 100ms
```

## 🛠️ 问题排查指南

### 1. 处理帧率过低 (< 20fps)

**可能原因**：
- 像素计算耗时过长
- 频繁的内存分配/释放
- 线程锁竞争激烈

**排查步骤**：
```bash
# 检查详细性能日志，重点关注：
1. 像素计算时间是否 > 15ms
2. 缓存命中率是否 < 50%
3. 获取视频帧时间是否异常
```

### 2. 缓存命中率过低

**可能原因**：
- 实时测温数据更新频率过低
- 缓存超时时间设置过短

**解决方案**：
```cpp
// 可以适当延长缓存超时时间
const auto cacheTimeout = std::chrono::milliseconds(1000); // 从500ms增加到1000ms
```

### 3. 温度矩阵更新不及时

**可能原因**：
- 视频流获取延迟
- 实时温度数据无效
- 线程阻塞

**诊断命令**：
```bash
# 检查日志中是否有以下信息：
- "输入视频帧为空"
- "温度条区域超出图像边界"  
- "缓存=未命中" 频繁出现
```

## 🚀 优化建议

### 短期优化 (立即可实施)

1. **查找表优化**
   ```cpp
   // 预计算灰度值→温度值映射表
   std::vector<float> createTemperatureLUT(float minTemp, float maxTemp, 
                                           const std::vector<float> &palette);
   ```

2. **减少图像拷贝**
   ```cpp
   // 使用引用而非拷贝
   const cv::Mat &frame = data_.thermal_video_frame_1; // 避免拷贝
   ```

3. **调色板缓存**
   ```cpp
   // 缓存调色板数据，减少重复提取
   static std::vector<float> cachedPalette;
   static bool paletteValid = false;
   ```

### 中期优化 (需要较大改动)

1. **多线程处理**
   - 将像素计算分解到多个线程
   - 使用OpenMP并行化循环

2. **SIMD优化**
   - 使用AVX/SSE指令集加速像素处理
   - 批量处理多个像素

3. **GPU加速**
   - 使用CUDA或OpenCL进行像素级并行计算
   - 图像预处理GPU加速

### 长期优化 (架构级改进)

1. **流水线处理**
   - 将图像获取、处理、存储分离到不同线程
   - 使用生产者-消费者模式

2. **自适应处理频率**
   - 根据系统负载动态调整处理频率
   - 智能跳帧策略
