# FFmpeg 硬件解码与内存池优化

## 🚀 新增功能

### 1. AMD 硬件解码支持
- **自动检测**: 程序会自动尝试AMD AMF硬件解码器
- **智能回退**: 硬件解码失败时自动回退到软件解码
- **支持编解码器**: H.264 (h264_amf) 和 HEVC (hevc_amf)
- **硬件加速**: 使用D3D11VA硬件设备上下文

### 2. 内存池优化
- **预分配**: 避免频繁的内存分配/释放
- **自定义缓冲区**: 使用自定义get_buffer2回调
- **动态调整**: 根据实际帧大小动态调整池大小
- **32字节对齐**: 优化内存访问性能

## 📊 性能提升预期

### 硬件解码优化
```
软件解码 (CPU):  2-25ms
硬件解码 (AMD):  0.3-1ms  ⚡ 提升5-50倍
```

### 内存分配优化
```
默认分配器:     每帧0.1-0.5ms内存开销

```

## 🔧 使用方法

### 编译要求
确保您的FFmpeg构建包含以下组件：
- `libavutil/hwcontext.h`
- `libavutil/hwcontext_d3d11va.h`
- AMD AMF解码器支持

## 🛠️ 技术特性

### 智能硬件解码器选择
1. **优先级排序**: h264_amf > hevc_amf > 软件解码
2. **兼容性检查**: 自动匹配流编解码器类型
3. **错误处理**: 硬件初始化失败时安全回退

### 高效内存池管理
1. **预分配策略**: 1080p YUV420P缓冲区 (~3MB)
2. **动态扩容**: 根据实际帧大小自动调整
3. **池大小限制**: 最大8个缓冲区避免内存过度占用
4. **线程安全**: 使用互斥锁保护池操作

### 优化配置参数
- **缓冲区对齐**: 32字节对齐优化SIMD指令
- **设备上下文**: D3D11VA硬件设备上下文
- **低延迟标志**: 保持原有的零延迟优化配置

## 🔍 故障排除

### 硬件解码失败
1. **检查驱动**: 确保AMD显卡驱动程序最新
2. **检查FFmpeg**: 验证FFmpeg是否包含AMF支持
3. **检查系统**: Windows 10/11 + DirectX 11支持

### 内存池异常
1. **内存不足**: 系统可用内存不足时会回退到默认分配器
2. **大帧处理**: 超大分辨率时会动态调整池大小
3. **线程竞争**: 高并发时使用互斥锁保护

## 💡 最佳实践

1. **监控日志**: 关注初始化日志确认硬件解码状态
2. **性能测试**: 对比硬件/软件解码的性能差异
3. **系统资源**: 硬件解码时GPU使用率会增加
4. **错误恢复**: 硬件解码异常时自动回退机制

---

**注意**: 硬件解码的实际性能提升取决于您的AMD显卡型号、驱动版本和FFmpeg构建配置。新版AMD Radeon RX系列显卡通常有最佳的AMF支持。
